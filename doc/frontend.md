# Клиентская архитектура

## Рендеринг и DOM

Главная страница целиком описана в `templates/index.html.twig`, календарный
фрагмент — в `templates/calendar-fragment.html.twig`. Страница использует
семантические `header`, `nav`, `main`, `footer`, нативные немодальные `dialog`
и календарную `table` с `tbody` из шести строк.

JavaScript находится в одном ES-модуле `public/script.js`. Для текущего объёма
это сохраняет поведение в одном месте и не требует дополнительных production
запросов, npm или build step.

Основные DOM-контракты задаются не презентационными классами, а атрибутами:

| Контракт | Назначение |
| --- | --- |
| `data-initial-calendar-route` | Серверный маршрут при загрузке URL без hash. |
| `data-calendar-route` | Публичный маршрут месяца или дня. |
| `data-calendar-direction` | Направление стрелки для восстановления keyboard focus. |
| `data-panel-target` / `data-panel` | Связь кнопки с dialog-панелью. |
| `data-tooltip` | Безопасный текст подсказки. |
| `data-calendar-view` | Корень динамически заменяемого календаря. |
| `data-region` | Постоянные области статуса, календаря и viewer. |

ID используются для реальных HTML/ARIA-связей, а CSS-классы — для оформления.
Новые обработчики не должны зависеть от разбора случайного ID или от
презентационного имени класса.

## Hash-навигация

Поддерживаются два публичных формата:

- `#dYYYY_M` — показать месяц;
- `#dYYYY_M_D` — показать месяц и открыть публикацию дня.

Год содержит от одной до четырёх цифр, месяц ограничен `1..12`, день —
`1..31`. Серверная проверка остаётся окончательной для year/month. Ссылки дней
имеют настоящий `href` на full-size JPG и отдельный `data-calendar-route`,
поэтому назначение ссылки остаётся понятным без поведенческих CSS-классов.

При первом открытии явный URL hash имеет приоритет. Если hash отсутствует,
скрипт использует переданный сервером `data-initial-calendar-route`; браузерный
`new Date()` не участвует, поэтому сервер и клиент не расходятся на границе
года или timezone.

`hashchange` обслуживает Back/Forward. Повторная активация уже текущего hash
явно запускает тот же обработчик, поскольку браузер не создаёт новое событие.

## Загрузка календаря

Клиент отправляет `application/x-www-form-urlencoded` POST на `/handler.php` с
`month` и `year`. Timeout составляет 30 секунд, предыдущий запрос отменяется
через `AbortController`.

Защита от гонок основана на версии маршрута и проверке активного request:

1. новый переход отменяет предыдущий request;
2. только актуальный request может заменить календарь;
3. только он меняет сообщение и `aria-busy`;
4. отменённые fade-анимации не могут оставить новый календарь прозрачным;
5. после keyboard-перехода focus возвращается на стрелку того же направления.

Ошибка или timeout оставляет последний успешно показанный календарь на месте и
выводит сообщение в постоянную alert/status-область. После успешной загрузки
отдельный live-region кратко объявляет месяц, не заставляя screen reader читать
всю таблицу.

## Dialog-панели и viewer

Панели `months`, `about` и `authors` постоянно присутствуют в DOM и открываются
нативным `dialog.show()` как немодальные окна. Одновременно открыто не более
одного dialog.

- кнопка повторно открывает/закрывает свою панель как toggle;
- открытие другой панели заменяет текущую;
- клик внутри окна ничего не закрывает;
- клик снаружи закрывает окно, не перехватывая focus;
- Escape и toggle возвращают focus исходной кнопке;
- `aria-expanded`, `aria-controls` и `aria-labelledby` синхронизированы с
  нативным состоянием dialog.

Viewer переиспользует один `dialog` и один `img`. Он корректно обрабатывает и
обычное событие `load`, и уже закешированное изображение через состояние
`complete`. Ошибка загрузки не открывает viewer. Закрытие viewer для day-route
переводит hash к соответствующему month-route.

Версии dialog-анимаций и сохранённые opener-элементы защищают от быстрых
повторных действий: устаревшая анимация не может снова открыть окно или
переместить focus.

## Tooltip и безопасность DOM

Tooltip — один постоянный элемент с `role="tooltip"`. События мыши и focus
делегируются от документа, поэтому одинаково работают для начальной страницы и
нового календарного фрагмента. Текст записывается через `textContent`; HTML из
manifest не интерпретируется.

Та же граница безопасности действует на сервере: Twig autoescape включён, а
`raw` запрещён тестом. Изменение заголовка публикации не должно требовать
ручного экранирования в PHP или JavaScript.

## Анимации и accessibility

Обычные fade-длительности сохраняют историческое поведение: 400 мс для UI и
1000 мс для календаря. При `prefers-reduced-motion: reduce` сразу применяется
конечное состояние.

Календарь содержит визуально скрытые заголовки семи дней недели. Сегодняшняя
ячейка получает `aria-current="date"`, пустые ячейки — `aria-hidden`. Ссылки
публикаций имеют полное имя с числовой датой и заголовком. Стрелки за пределами
годов `1..9999` визуально сохраняются, но выводятся без `href` и route, с
`aria-disabled="true"`.

Любое изменение DOM или поведения следует проверить мышью и клавиатурой:
hash/Back/Forward, focus после стрелок и dialogs, Escape, внешний клик,
tooltip, viewer, ошибку изображения, request race и reduced motion.

## Визуальный контракт

Дизайн остаётся desktop-only с оболочкой общей шириной 908 px: 708 px content
и горизонтальные padding по 100 px. Геометрия календаря, панелей и viewer
закреплена Playwright screenshots при viewport 908 px. CSS reset и служебные
приёмы для доступного `thead` учитывают legacy-геометрию; их нельзя упрощать без
визуального сравнения и проверки доступности.
