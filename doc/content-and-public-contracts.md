# Контент и публичные контракты

## Manifest архива

`content/archive.json` — единственный источник опубликованных дней,
заголовков и исходных дат публикации. Это JSON-массив из объектов точной формы:

```json
{
  "month": 3,
  "day": 1,
  "title": "Заголовок публикации",
  "publishedAt": "2009-03-01T04:00:00Z"
}
```

`CalendarArchive` лениво читает manifest один раз на экземпляр и индексирует
заголовки по `month/day`, а также предоставляет типизированный список
публикаций для RSS. Проверяются:

- корневой JSON-массив;
- точный набор полей `month`, `day`, `title`, `publishedAt`;
- настоящие JSON integers для месяца и дня;
- месяц `1..12` и реальная повторяемая дата, включая 29 февраля;
- непустой строковый title;
- строгий UTC-формат `YYYY-MM-DDTHH:MM:SSZ` и совпадение месяца/дня
  `publishedAt` с календарной датой;
- отсутствие двух записей на один `month/day`.

Календарное отображение остаётся повторяемым: публикации видны в том же месяце
и дне любого запрошенного года. `publishedAt` хранит исходный исторический год
только для RSS. Для проверки допустимости 29 февраля используется високосный
опорный год.

Ошибка чтения или валидации — явная ошибка данных и HTTP 500. Fallback
`no subject` больше не существует.

## Изображения

Для каждой записи manifest должны существовать два canonical-файла:

```text
public/blog/{month}_{day}_thmb.jpg
public/blog/{month}_{day}_full.jpg
```

URL вычисляются во view-слое по соглашению об именах. `CalendarArchive` не знает
о web-путях, а production request не сканирует директорию и не проверяет файлы:
целостность manifest и canonical image pairs в обе стороны гарантирует
`ContentIntegrityTest` перед выпуском.

Дополнительные варианты вида `3_28_thmb_1.jpg` и `3_28_full_1.jpg` допустимы,
если образуют пару. Они остаются доступными статическими файлами, но не создают
новую публикацию и не влияют на counts.

Текущее содержимое: 53 публикации. Counts с января по декабрь:
`[5, 2, 27, 5, 2, 2, 1, 2, 1, 0, 2, 4]`.

## Как изменить архив

Для добавления публикации:

1. Добавить одну запись с уникальным `month/day`, заголовком и исходным UTC
   `publishedAt` в `content/archive.json`.
2. Добавить matching thumbnail и full-size JPG с canonical-именами.
3. Выполнить `docker compose --profile test run --rm rss`, чтобы обновить RSS.
4. Запустить проверки: они проверят схему, даты, XML и соответствие файлов.
5. Проверить календарь и viewer через Playwright или локальный браузер.

Для изменения title достаточно изменить manifest и проверить экранирование и
видимый текст, затем перегенерировать RSS. Для удаления нужно удалить запись,
оба canonical-изображения и снова сгенерировать RSS.

Не создавать обратно месячные `.txt`: runtime их не читает, а тест явно
проверяет, что legacy title files отсутствуют.

## RSS

`public/rss.xml` — детерминированный generated-файл из manifest и
`templates/rss.xml.twig`. Он хранится в Git и раздаётся статически: PHP и Twig
не участвуют в HTTP-запросе `/rss.xml`.

`composer rss` обновляет файл, а `composer rss:check` проверяет его без записи.
Каждая запись manifest становится item; порядок определяется `publishedAt` от
новых к старым, а channel `pubDate` равен самой новой публикации. Публичные
ссылки и изображения используют HTTPS. GUID намеренно сохраняет legacy HTTP
формат `http://calendorama.dgroza.ru/blog/{month}_{day}_thmb.jpg`, чтобы
существующие RSS-клиенты не приняли прежние записи за новые.

## HTTP-контракты

| Endpoint | Метод и вход | Ответ |
| --- | --- | --- |
| `/` | GET | Главная HTML-страница, 200. |
| `/index.php` | GET | Та же главная страница, 200. |
| `/handler.php` | GET `month=1..12`, `year=1..9999` | HTML `<section>` календаря, 200 и `Cache-Control: no-store`. |
| `/handler.php` | Нет или некорректные GET-параметры | `Invalid calendar date.`, 400. |
| `/handler.php` | POST и другие методы | `Method Not Allowed.`, 405 и `Allow: GET`. |
| `/rss.xml` | GET | Сгенерированный статический RSS с `Cache-Control: no-cache`. |
| `/style.css`, `/script.js`, `/favicon.ico`, `/blog/*` | GET | Статические публичные файлы. |

HTML fragment handler сохраняет 6 недель и 42 ячейки даже для коротких
месяцев. На границах year 1 и 9999 соседняя стрелка присутствует только как
неинтерактивный элемент.

Публичные hash-форматы — `#dYYYY_M` и `#dYYYY_M_D`. Они являются частью URL
контракта, хотя сам fragment получает только month/year.

## Граница web-root

Только `public/` доступен через Nginx. В частности, извне должны получать 404:

- `/content/archive.json`;
- `/src/`, `/templates/`, `/tests/`, `/vendor/`;
- `/function.php` и любой произвольный PHP-файл;
- удалённые legacy-файлы `/blog/{month}.txt`.

Выполнение PHP разрешено только для `/index.php` и `/handler.php`. Новый PHP
endpoint требует явного архитектурного решения и изменения allow-list в обеих
Nginx-конфигурациях и HTTP smoke-тесте.
