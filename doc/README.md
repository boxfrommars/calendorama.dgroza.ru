## Быстрое знакомство с проектом

Calendorama — небольшой read-only календарный архив. PHP 8.3 формирует главную
страницу и HTML-фрагменты календаря через Twig. Браузер загружает и переключает
месяцы одним ES-модулем без frontend build step. Базы данных, пользовательских
загрузок, изменяемого серверного состояния и фоновых задач нет.

Основные точки входа:

- `public/index.php` создаёт главную страницу;
- `public/handler.php` принимает месяц и год и возвращает календарный фрагмент;
- `content/archive.json` задаёт опубликованные дни и заголовки;
- `templates/` содержит весь генерируемый HTML;
- `public/script.js` реализует клиентское поведение;
- `src/ApplicationFactory.php` явно собирает приложение и его зависимости.

Для первого изменения полезно прочитать документацию в таком порядке:

1. [Архитектура приложения](architecture.md).
2. Документ о затрагиваемом слое: frontend или контент.
3. [Тестирование и эксплуатация](testing-and-operations.md).

## Источники истины

Если документация расходится с проектом, приоритет имеют исполняемый код,
тесты и конфигурация. В частности:

- схема архива определяется проверками `CalendarArchive`;
- DOM-контракты закреплены Twig-шаблонами, JavaScript и DomCrawler-тестами;
- поведение в браузере закреплено Playwright-сценариями;
- web-доступ и заголовки определяются Nginx-конфигурацией;
- точные версии пакетов определяются lock-файлами.

При изменении архитектуры, публичного контракта, формата контента или порядка
выпуска соответствующий документ нужно обновить в том же commit.
